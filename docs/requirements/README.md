# requirements/ — 요구사항 추적 (살아있는 문서)

요구 하나가 **근거 → 만든 것 → 시험 → PR → 반영**까지 어떻게 이어졌는지 요구 번호로 한 줄에 답하게 한다.

- **추적표 = `trace.md` 한 파일** (번호 | 요구 | 근거 | 만든 것 | 시험 | PR | 상태). 요구를 받으면 바로 한 줄 등록.
- 분석이 길어지는 요구만 `<번호>-제목.md` 상세 파일 (`_templates/requirement.md`) — 표의 `요구` 칸에서 링크.
- **번호 체계는 프로젝트가 정한다** (예: `REQ-012`·`SFR-001`·고객 RFP 번호 그대로). 정한 형식은 `trace.md` 맨 위 `id-format:` 에 적는다.
  - 한 번 쓴 번호는 재사용하지 않는다. **`#` 으로 시작하는 번호는 피한다** (GitHub 이 이슈 링크로 바꿈 — `docs/guides/pr-rules.md`).
  - 아래 예시는 `REQ-012` 기준 — 프로젝트 번호로 바꿔 읽는다.

## 규칙 — 표가 낡아도 다시 만들 수 있게
- **커밋 메시지·PR 제목에 요구 번호**: `[REQ-012] 반품 수량 상한 검사` (`#` 붙이지 않음).
- **시험 이름에 요구 번호**: `test_req012_return_qty_limit` (식별자에 못 쓰는 문자는 빼고 소문자).
- 표를 다시 맞출 때는 `guides/req-trace.md` 절차 — 번호로 커밋·PR·시험을 검색해 채운다.

`check_docs.py` 검사: 표의 번호가 비었거나 **중복**이면 오류, 상태 값이 정해진 것 밖이면 경고. (번호 **형식은 검사하지 않음**)
