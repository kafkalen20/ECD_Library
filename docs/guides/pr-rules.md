# PR 작성 규칙 (회사 공통)

> ⚠️ **kit 엔진 파일** — `claude-brain`(회사 팀 지식 kit)에서 동기화된다. **이 프로젝트에서 직접 고치지 말 것.**
> 고칠 게 생기면 kit에 반영한다(`/claude-brain` 역반영). 프로젝트 고유 규칙(브랜치·커밋 접두어 등)은 `docs/guides/gitflow.md`.
>
> **AI는 PR·커밋 메시지를 쓰기 전에 이 파일을 반드시 읽는다.** 아래 규칙은 CI(`docs-guard`)가 강제한다.

## PR 설명 = 필수 (강제됨)
모든 PR은 **템플릿 5섹션**을 채운다. `.github/pull_request_template.md` 가 새 PR 설명칸을 자동으로 채워주고,
**CI(`docs-guard` / PR 설명 템플릿 검사)가 4섹션(What·Why·How·Gotchas)을 강제**한다 — 비면 PR이 실패한다.

| 섹션 | 뭘 쓰나 |
|---|---|
| **무엇을 (What)** | 이 PR이 바꾸는 것 한두 줄 |
| **왜 (Why)** | 어떤 요구사항/문제 때문인가 (관련 이슈 배경) |
| **어떻게 (How)** | 핵심 접근·건드린 파일/메서드·코어 변경 여부 |
| **주의·함정 (Gotchas) ★** | 나중에 이 코드를 만질 사람이 모르면 위험한 것. 없으면 `없음` |
| **관련 (Issue / 문서)** | `Closes #N` · 요구 번호(예 `REQ-012`) · 헬프데스크 `티켓 00124`(**`#` 금지**, 아래 참고) · 남긴 ADR/이슈 문서 링크 |

### 규칙
- **헤더는 템플릿의 한글 그대로** 쓴다: `## 무엇을 (What)` · `## 왜 (Why)` · `## 어떻게 (How)` · `## 주의·함정 (Gotchas)` · `## 관련`. 영문 헤더(`## What` 등)로 바꾸면 CI 실패.
- **자리표시자(`<...>`)를 그대로 두면 CI 실패.** 실제 내용으로 채운다.
- Gotchas가 정말 없으면 비우지 말고 **`없음`** 이라고 적는다 (검사 통과).
- CLI(`gh pr create`)로 만들 때도 `--body` 에 5섹션을 넣는다 (웹 UI 아니면 템플릿이 자동으로 안 들어감).

### 예시
```markdown
## 무엇을 (What)
매입매출·구매전용의 예약 차감을 sale_only·internal 이동으로만 제한

## 왜 (Why)
자기 입고분을 되파는 구조라, 전량 차감하면 직출 시 재고가 음수가 된다

## 어떻게 (How)
buysell 예약 로직 5곳에서 매입매출/구매전용 차감 제거. 코어 무변경.

## 주의·함정 (Gotchas) ★
되파는 재고엔 '예약' 개념 자체가 성립 안 함 — 다음에 전량 차감으로 되돌리지 말 것

## 관련 (Issue / 문서)
- Closes #98 · docs/decisions/0002-예약정책.md
```

## 헬프데스크 티켓 번호 표기 ★ (`#` 금지)
PR 제목·본문·커밋 메시지·GitHub 코멘트에 헬프데스크 티켓 번호를 **`#00124` 처럼 `#` 을 붙여 쓰지 않는다.**
GitHub 은 앞자리 0 을 무시하고 이 저장소의 **이슈/PR #124 로 자동 연결**한다 → 전혀 다른 이슈에
"PR 에서 언급됨" 기록이 남고, 이 기록은 본문을 고쳐도 지워지지 않는다.

| ❌ 쓰지 말 것 | ✅ 이렇게 |
|---|---|
| `헬프데스크 #00124` | `헬프데스크 티켓 00124` |
| `(#00005 #00058)` | `(티켓 00005 00058)` |
| 제목 `... (#00055)` | 제목 접두 `[00055] ...` 또는 `(티켓 00055)` |

- GitHub 이슈·PR 을 가리킬 때만 `#N`(예: `Closes #530`, `PR #707`)을 쓴다.
- 저장소 안 `.md` 파일(ADR·이슈 문서)은 자동 연결되지 않아 무방하지만, 헷갈리지 않게 같은 표기를 권장.

## 요구 번호 표기 ★ (요구사항 추적)
요구사항(`docs/requirements/trace.md`)에서 나온 작업은 **요구 번호를 남긴다** — 표가 낡아도 검색으로 다시 만들 수 있게(`docs/guides/req-trace.md`).
번호 **형식은 프로젝트가 정한다**(`trace.md` 의 `id-format:`). 아래는 `REQ-012` 예시.

| 어디 | 이렇게 |
|---|---|
| PR 제목 · 커밋 메시지 | 접두 `[REQ-012] 반품 수량 상한 검사` (여러 개면 `[REQ-012 REQ-015]`) |
| PR 본문 `## 관련` | `요구 REQ-012` |
| 시험 이름 | `test_req012_return_qty_limit` (식별자에 못 쓰는 문자는 빼고 소문자) |

- 티켓처럼 **`#` 을 붙이지 않는다** (`#012` → 이슈 #12 로 자동 연결됨). 번호 체계 자체가 `#` 으로 시작하면 앞에 접두(예 `REQ-`)를 붙여 쓴다.
- 요구와 무관한 작업(리팩터·설정 등)은 번호 없이 쓴다.

## 문서를 별도로 남길지
- 대부분은 위 PR 설명으로 **끝**.
- "6개월 뒤 코드·PR만 봐선 모를 게 있나?" → 있으면 `docs/ROUTING.md` 표대로 `decisions/`·`issues/` 등에 남긴다.
