# 요구 번호로 추적표 다시 맞추기 (회사 공통)

> ⚠️ **kit 엔진 파일** — `claude-brain`에서 동기화된다. **이 프로젝트에서 직접 고치지 말 것.** (고칠 게 있으면 `/claude-brain` 역반영)
>
> 커밋·PR 제목·시험 이름에 요구 번호를 남겨 두었기 때문에, 표가 낡아도 검색으로 다시 채울 수 있다.
> 번호 형식은 프로젝트마다 다르다 → `trace.md` 의 `id-format:` 을 먼저 보고, 아래 예시(`REQ-012`)를 그 형식으로 바꿔 쓴다.
> 어느 AI든 사람이든 이 순서대로 한다. Claude Code는 `/req-trace [번호]` (번호를 안 주면 표 전체).

## 순서
1. **대상 번호 정하기** — 지정한 번호, 없으면 `docs/requirements/trace.md` 의 상태가 `반영`·`취소`가 아닌 줄 전부.
2. **번호별로 검색** (시험 이름처럼 구분자가 빠진 표기도 같이 찾는다):
   ```bash
   git log --all --oneline -i -E --grep='REQ-?012'                 # 커밋
   gh pr list --state all --search 'REQ-012' --json number,title,state,mergedAt   # PR (제목·본문)
   grep -rniE 'req-?012' --include='*.py' --include='*.js' --include='*.xml' .  # 시험·코드
   grep -rn 'REQ-012' docs/                                        # 설계·결정·이슈 문서
   ```
3. **표 갱신** — 찾은 것으로 `만든 것`·`시험`·`PR`·`상태` 칸을 채운다. 상태 판단 기준:
   - PR 없음 → `요청`/`분석` 유지 · PR 열림 → `개발` · 시험 이름/기록 있음 + PR 머지 → `시험`
   - **`반영`(운영 적용)은 검색으로 단정하지 않는다** — 배포 기록(`guides/deploy.md` 이력·PR)으로 확인되거나 사람이 확인한 것만.
4. **보고** — 번호마다 한 줄: `<번호> | 바뀐 칸 | 근거(커밋·PR 번호)`. 검색에 아무것도 안 걸린 번호는 **❗근거 없음**으로 따로 모은다(번호를 안 남긴 작업일 수 있음 — 사람이 확인).
5. **검증** — `python3 scripts/check_docs.py`.

## 금지
- 검색으로 확인 안 된 PR·시험을 지어서 채우지 않는다. 모르면 비워 두고 ❗로 보고.
