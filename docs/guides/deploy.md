# 고객사 프로젝트에 모듈 적용 (복사 방식)

> 이 레포는 고객사 서버에 직접 배포하지 않는다. **필요한 모듈 폴더만 고객사 프로젝트 레포로 복사**하고, 그 뒤 운영 반영은 **고객사 프로젝트의 배포 절차**를 따른다.
> 사람이 확인하며 실행한다(AI는 단독 실행 금지). Claude Code는 `/deploy`(사람만 호출)가 이 문서를 불러 순서대로 안내한다.
> 접속정보·비밀값은 이 문서에 적지 않는다 — 비밀번호 관리자에서 조회.

## 순서
1. **버전 확인** — 고객사 Odoo 버전과 같은 폴더(`19.0/` 등)에서 가져온다. 다른 버전 폴더 모듈을 그대로 쓰지 않는다.
2. **모듈 고르기** — 쓸 모듈 + `depends`에 걸린 이 레포 모듈을 함께 고른다 (예: `barobill_sms` → `barobill` 필수, `edb_helpdesk` → `edb_common` 필수). 의존 관계 → `docs/project/modules.md`
3. **복사** — 모듈 폴더째 고객사 레포의 addons 경로로 복사 (`__pycache__` 제외).
4. **Python 의존성** — `__manifest__.py` `external_dependencies` 확인 (바로빌: `zeep`, 일부 `pytz`) → 고객사 서버에 설치되어 있는지 확인.
5. **고객사 레포에 커밋** — 커밋 메시지에 출처 남김: `ECD_Library <버전폴더> @ <커밋 해시>` (나중에 어느 시점 코드인지 추적용).
6. **고객사 운영 반영** — 고객사 프로젝트 배포 절차대로 (DB 백업 → `odoo-bin -u <module>` 또는 신규 설치 → 재시작 → 로그 확인).
7. **설정 입력** — 바로빌 등 비밀값은 설치 후 설정 화면에서 직접 입력 (테스트 모드로 먼저 확인).

## 주의 (Gotchas)
- 복사본은 이 레포와 자동 동기화되지 않는다. 이 레포에서 버그를 고치면 쓰는 고객사 레포에 **다시 복사**해야 한다.
- 고객사 레포에서 복사본을 직접 고쳤다면, 공통으로 쓸 수정은 이 레포에도 반영한다(고객사 전용 수정은 이 레포에 넣지 않는다).
- 이전 Odoo 버전 폴더는 쓰는 고객사가 있을 때만 유지보수한다.
- 바로빌 `prod` 모드는 실제 발송·포인트 차감 — 설정 확인 전 운영 모드로 두지 않는다.
