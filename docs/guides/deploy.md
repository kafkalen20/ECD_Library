# 운영 배포 절차

> [❓확인 필요: 이 공용 레포의 "배포"가 무엇인지 — 사용 프로젝트로 모듈을 옮기는 방식(submodule·복사·addons_path)과 사내 운영 인스턴스 유무. 첫 배포 때 같이 실행하며 아래를 고쳐 쓴다.]

> 사람이 확인하며 실행한다(AI는 단독 실행 금지). Claude Code는 `/deploy`(사람만 호출)가 이 문서를 불러 순서대로 안내한다.
> 실제 접속정보·경로는 비밀번호 관리자/배포도구 secrets에서 조회한다 — **이 문서에 값을 적지 않는다.**
> 처음 운영 배포 때 한 번 같이 실행하며 받아쓰면 정확해진다. 아래는 Odoo 기준 예시 — 프로젝트에 맞게 고친다.

## 순서
1. **사전 점검** — 배포할 커밋·모듈 버전 확인, 변경 파일 목록 확인
2. **DB 백업** — 배포 전 운영 DB 백업 (백업 파일명·시각 기록)
3. **코드 업로드** — 단일 연결로(연결을 여러 번 열면 방화벽에 IP 차단될 수 있음)
4. **모듈 반영** — `odoo-bin -u <module>` (화면 '업그레이드' 버튼 금지, 반드시 명령어)
5. **서비스 재시작**
6. **상태 점검** — 포트 LISTEN, HTTP 200, 로그 클린 확인
7. **기록** — 배포 버전·백업 위치·롤백 방법을 PR 또는 아래 `## 배포 이력`에 남김

## 주의 (Gotchas)
- 인증 실패 시 즉시 중단(재시도가 IP 밴을 키움). 밴 위험이 있으면 배포하지 않고 승인받는다.
- 배포만으로 컴파일 자산 번들이 자동 재생성되지 않을 수 있음 — JS 반영 안 되면 번들 재생성 필요.
