# 문서 라우팅 규칙 — 언제 / 어디에 남기나 (단일 진실원)

> 이 파일이 "무엇을 언제 어디에 기록하는가"의 **유일한 기준**이다.
> AI와 사람 모두 여기를 따른다. 임의 폴더 저장 금지.
> 진입 파일(AGENTS.md/CLAUDE.md)과 문서 작성 절차(`docs/guides/write-doc.md`·`/write-doc` 스킬), CI 검사(check_docs.py)가 전부 이 표를 근거로 동작한다.

## 0. 첫 번째 질문 (문서를 만들지 말지)

> **"6개월 뒤 다른 사람/AI가 코드·PR만 봐서는 모를 게 있나?"**
> - **없다** → 문서 만들지 마라. **PR 설명(What/Why/How/Gotchas)으로 끝.**
> - **있다** → 아래 표에서 유형을 골라 해당 폴더에 남긴다.

## 1. 라우팅 표 (트리거 → 위치 → 누가/언제 → 템플릿)

|---|---|---|---|---|---|
| 1 | 운영 장애 · 데이터 정정 · 배포 실패 · 30분+ 대응 · 데이터 손실/불일치 · **작업 사고**(다른 PR 덮어쓰기·잘못된 대상 수정·잘못된 안내 발송 등) | `docs/issues/` | **AI가 작업 종료 시 자동 초안** → 사람 확인 | `issue.md` | `YYYY-MM-DD-무엇-어디.md` |
| 2 | 비자명한 설계 판단 · 아키텍처/코어 변경 · 여러 모듈 걸침 · "왜 이 방식?"이 남는 결정 | `docs/decisions/` | **AI가 PR과 함께 자동 초안** → 사람 확인 | `decision.md` | `NNNN-제목.md` (마지막번호+1) |

## 2. 판단 플로우

```text
작업 완료
   │
   ├─ 운영 장애/데이터 정정/배포 실패/작업 사고? ─ 예 → [1] issues/  (AI 자동 초안)
   │
   ├─ 코드·PR만 봐선 모를 '설계 판단'이 있나? ── 예 → [2] decisions/   (AI 자동 초안, 기각한 대안 포함)
   │
   ├─ 반복 절차를 새로 알게 됐나? ───────────── 예 → 사람판단? [3] guides/  /  AI반복? skills/
   │
   ├─ 프로젝트 구조/모듈/고객사 지식인가? ────── 예 → [4] project/  (compass·overview·customer-*)
   │
   ├─ 구현 전 큰 기능 설계/목업인가? ─────────── 예 → [5] design/  (초안→확정→구현완료)
   │
   ├─ 다른 세션/사람이 이어받을 미완 작업인가? ── 예 → [6] handoff/  (끝나면 삭제)
   │
   ├─ 사람·외부에 보내는 문서인가? ────────────── 예 → [7] delivery/  (초안 → 사람 확인 후 발송)
   │
   ├─ 새 요구를 받았나? ──────────────────────── 예 → [10] requirements/trace.md 한 줄
   │
   └─ 그 외(일상 개발) ───────────────────────── [11] PR 설명으로 끝 (파일 X)

   + 일이 끝날 때마다: status.md·schedule-scope.md 등 갱신 목록 → guides/task-done.md
```

## 3. 엉뚱한 폴더 방지 규칙 (강제)

각 폴더는 **고유한 파일명 규칙 + 필수 표식**을 가진다. `scripts/check_docs.py`(로컬 hook + CI)가 이를 검사해 위반 시 막는다.

| 폴더 | 파일명 규칙 | 필수 표식 | 내용 시그니처(다른 폴더에 있으면 오류) |
|---|---|---|---|
| `decisions/` | `NNNN-*.md` (4자리 번호) | `status:` frontmatter | `## 기각한 대안` |
| `issues/` | `YYYY-MM-DD-*.md` | `owner:` + `## 5 Whys` | `## 5 Whys` |
| `delivery/` | `YYYY-MM-DD-*.md` | `to:` + `## 가정한 것`(비면 오류) | — |
| `requirements/` | 자유 (번호 형식은 프로젝트가 정함) | 표 번호 빈칸·중복 금지 (상태 값은 경고) | — |
| `status.md` | 고정 | 40줄·한 줄 300자 이하 (20줄 넘으면 경고) | — |
| `guides/` `project/` `design/` `handoff/` | 자유 (README 제외) | 살아있는 문서엔 `owner:` | — |

- 예: `## 5 Whys`가 들어간 파일이 `project/`에 있으면 **"장애기록 내용이 잘못된 폴더에 있음"** 오류 → issues/로 옮겨야 통과.
- 예: `decisions/`에 `NNNN-` 번호 없는 파일명 → 오류.
- 새 문서를 추가하면 `docs/README.md` 목차에 한 줄 등록 (미등록 시 경고).
- `handoff/`의 `status: 완료` 또는 30일 넘게 안 고친 인계 → 정리 안내(경고).
- `docs/`가 git 밖이거나 `.gitignore`로 빠져 있으면 경고 — 공유·이력·자동검사가 안 먹히는 근본 원인.
- **어디서 강제되나:** 로컬 = `.githooks/pre-commit`(커밋 차단, 어느 AI·사람이든) + Claude hook(저장 시 즉시 표시) / CI = `docs-guard.yml`(PR 차단).

## 4. 누락 방지 (개발자가 까먹어도)

- **1차(주 방어): AI가 자동 초안.** 진입 파일 규칙에 따라, AI는 작업 종료 시 트리거 1·2를 스스로 판단해 초안을 만들고 사람에게 확인받는다.
- **2차(백스톱): CI 강제.** PR이 `scripts/` 또는 `migration/`을 바꿨는데 `issues/`·`decisions/` 문서가 하나도 없으면 **PR 검사 실패**.
  - 예외가 정당하면 **PR 본문 줄 맨 앞에 `[no-doc] 사유`** 를 한 줄 남기면 통과. (커밋 메시지 줄 맨 앞도 인정 — 하위호환)
  - 설명 문장 중간이나 코드 표기(`` `...` ``) 안의 `[no-doc]` 은 인정하지 않는다 — PR 템플릿 안내 줄을 그대로 둬서 통과되는 것 방지.
