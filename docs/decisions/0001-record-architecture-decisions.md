# 0001. 설계 결정을 ADR로 기록한다

## 맥락 (어떤 업무/요구사항)
AI가 코드의 대부분을 작성하면서 "왜 이렇게 했는지"가 git diff로 복원되지 않아,
시간이 지나면 다른 개발자·다른 AI가 변경 이유를 파악하지 못하는 문제가 있었다.

## 결정
비자명한 설계 판단을 `docs/decisions/`에 결정당 마크다운 1파일(ADR)로 남긴다.
번호는 마지막+1. 각 ADR은 맥락·결정·**기각한 대안(이유)**·결과를 담는다.
진입 파일(AGENTS.md/CLAUDE.md)은 얇게 두고 여기를 가리킨다.

## 기각한 대안 (결과가 아니라 이유로)
- 모든 작업을 문서화: 문서 폭발 + git과 중복 → 재사용될 결정만 남기기로.
- 위키/Notion에 보관: 코드와 분리되면 노후화("knowledge rot") → 레포 안 Git으로.
- 결정을 PR 설명에만: PR은 "무엇"엔 강하나 "기각한 대안"을 담기 어려움 → ADR 병행.

## 결과
- 대부분의 일상 작업은 PR 설명(What/Why/How/Gotchas)으로 끝난다.
- 비자명한 판단만 ADR로 승격 → 사람·AI 교체에도 "왜"가 남는다.
