# 전역 통합검색 (Global Search)

상단 시스트레이(네비바) 검색창 하나에서 **여러 모델을 여러 필드로 동시에** 검색하는
Odoo 19.0 커스텀 모듈. 어느 프로젝트에나 그대로 얹을 수 있도록 표준 Odoo(`base`, `web`)에만
의존하며, 검색 대상은 코드가 아니라 **화면 설정**으로 관리한다.

---

## 왜 쓰나

기존에는 거래처·상품·주문·청구서 등을 찾으려면 각 메뉴로 들어가 개별 검색해야 했다.
이 모듈은 상단 검색창 한 곳에서 **등록된 모든 모델을 한 번에** 훑어, 결과를 모델 그룹별로
보여준다. 클릭하면 해당 레코드 폼으로 바로 이동한다.

---

## 주요 기능

- **다중 모델 · 다중 필드 동시 검색** — 검색어 하나로 등록된 모든 대상 모델을 조회.
- **화면 설정으로 대상 관리** — 관리자가 설정 모델(`global.search.config`)에서 검색할
  모델·필드를 자유롭게 추가/제거 (코드 수정 불필요).
- **관계 필드 검색** — 거래처(`partner_id`) 같은 m2o는 표시명으로 검색.
- **o2m 하위 필드 검색** — 주문 라인(`line_ids`) 같은 o2m는 '하위 필드'를 골라
  라인 내부(품목·이력번호 등)까지 검색.
- **권한 존중** — 각 모델의 접근권한(ACL)·레코드 규칙(record rule)을 그대로 태워,
  사용자가 볼 수 있는 레코드만 결과에 노출.
- **결과 UX** — 그룹별 표시, 검색어 하이라이트, 키보드 내비게이션(↑ ↓ / Enter),
  그룹별 '전체보기'(> 아이콘)로 같은 조건의 목록뷰 열기.
- **부제(매칭 힌트)** — 검색어가 실제로 걸린 필드를 "라벨: 값" 형태로 표시.
- **성능 최적화** — o2m는 라인(comodel) 테이블을 1회만 검색해 부모로 매핑하여
  상관 서브쿼리를 피한다.

---

## 설치

1. `global_search` 폴더를 대상 프로젝트의 `addons/` 경로에 복사한다.
2. 앱 목록 새로고침 후 설치하거나, CLI로:
   ```bash
   odoo-bin -c <config> -d <db> -i global_search
   ```
3. 설치 후 상단 네비바 오른쪽에 검색창이 나타난다.

> 의존성은 `base`, `web`뿐이라 어떤 Odoo 프로젝트에나 충돌 없이 얹힌다.

## 검색 대상 설정

기본 시드가 없으므로 **설치 직후에는 검색 대상이 비어 있다.** 관리자가 직접 등록한다.

1. 개발자 모드를 켠다.
2. **설정 > 기술 > 사용자 인터페이스 > 통합검색** 메뉴로 이동.
3. 대상 모델을 추가하고, 검색할 필드를 지정한다.
   - **필드 가져오기** 버튼: 모델의 검색 가능 필드를 한 번에 추가한 뒤 불필요한 것 삭제.
   - **하위 필드**: o2m/관계 필드를 고르면 그 대상 모델의 세부 필드를 골라 담을 수 있다.

### 설정 항목

| 항목 | 설명 |
|------|------|
| 대상 모델 | 검색할 모델 (모델당 설정 1개). |
| 표시 라벨 | 결과 그룹 제목. 비우면 모델 이름 사용. |
| 검색 대상 필드 | 검색할 필드 목록. 관계 필드는 하위 필드로 세분화 가능. |
| 제목 필드 | 결과 제목에 쓸 경로(선택). 라인 모델처럼 자체 이름이 없을 때 부모 정보 사용. 예: `order_id.name` |
| 최대 결과 수 | 이 모델에서 한 번에 표시할 결과 개수(기본 8). |
| 순서 | 결과 그룹 정렬 순서. |

### 설정 예시

- **거래처**: `res.partner` → `name`, `ref`, `phone`
- **상품**: `product.template` → `name`, `default_code`, `barcode`
- **판매주문**: `sale.order` → `name`, `partner_id`
- **주문 라인 내부 검색**: `sale.order` → `line_ids`(필드) + 하위 필드 `product_id`

> 위 예시의 `sale.order` 등은 해당 모듈이 설치된 프로젝트에서만 등록 가능하다
> (이 모듈 자체는 그 모듈들에 의존하지 않는다).

---

## 사용법

1. 상단 검색창에 **2글자 이상** 입력하면 자동으로 검색된다(300ms 디바운스).
2. 결과가 모델 그룹별로 드롭다운에 표시된다.
3. `↑` `↓` 로 이동, `Enter` 로 해당 레코드 폼 열기, `Esc` 로 닫기.
4. 그룹 제목 옆 `>` 아이콘 → 같은 검색 조건으로 목록뷰 전체보기.

## 구조

```
global_search/
├── __manifest__.py                     # depends: base, web
├── models/
│   └── global_search.py                # global.search.config / .line + search_global 서비스
├── security/
│   └── ir.model.access.csv             # 읽기: 전 사용자 / 관리: 시스템 관리자
├── views/
│   └── global_search_views.xml         # 설정 리스트·폼·메뉴
└── static/src/js/global_search/
    ├── global_search.js                # 시스트레이 OWL 컴포넌트
    ├── global_search.xml               # OWL 템플릿
    └── global_search.scss              # 스타일
```

### 모델

- **`global.search.config`** — 검색 대상 모델 설정. 메서드 `search_global(term)` 이
  실제 검색을 수행하며 그룹 리스트를 반환한다.
- **`global.search.config.line`** — 각 설정의 검색 대상 필드(+ o2m 하위 필드).

## 주의 · 함정

- **검색 대상은 설정 데이터에 의존한다.** 새 모델/필드를 넣으려면 코드가 아니라
  이 설정 화면에서 추가한다.
- **검색 불가 필드(계산형 o2m/m2m 등)** 가 섞이면 그 필드만 조용히 건너뛰고 전체 검색은
  계속된다. 특정 필드가 안 걸리면 그 필드의 검색 가능 여부부터 확인할 것.
- **결과는 사용자 권한에 따라 다르다.** ACL/레코드룰을 그대로 태우므로 권한 없는
  레코드는 나오지 않는다.
- o2m 성능 최적화는 라인 테이블을 먼저 훑어 부모로 매핑하는 구조라, 검색 대상 comodel이
  매우 크면 이 경로의 비용을 먼저 의심할 것.
- 필드 라벨 한글화 매핑(`_KO_FIELD_LABEL`)은 한국어 UI를 전제로 한 편의 기능이다.
  다른 언어 환경에서는 필드 정의의 라벨(string)로 자동 대체된다.
